# ADR 003: Using Hardhat Instead of Remix for Smart Contract Development

## Status

**Approved**

## Context

The ChainDegree project requires smart contract development as part of a professional software engineering workflow.

Possible development tools include:

- Remix IDE
- Hardhat

While Remix is easy for experimentation and learning Solidity, it lacks many capabilities required for collaborative development, automated testing, version control, and CI/CD integration.

## Decision

Hardhat is selected as the official smart contract development toolchain.

Remix may be used only for quick experimentation or debugging, but never for deployment or production workflows.

All contracts are developed, tested, and deployed through Hardhat scripts.

## Consequences

### Advantages

* **Infrastructure as Code**

Deployment becomes reproducible.

```
git clone

npm install

npx hardhat run deploy.ts
```

Every developer obtains exactly the same deployment process.

---

* **Automated Testing**

Hardhat provides:

- Unit Tests
- Integration Tests
- Fixtures
- Network Simulation

allowing contracts to be validated before deployment.

---

* **Version Control Friendly**

Deployment scripts are committed into Git.

Every deployment becomes reviewable.

---

* **CI/CD Ready**

Future pipelines can automatically execute:

```
Compile

↓

Unit Test

↓

Deploy

↓

Smoke Test
```

without human interaction.

---

* **Supports Multiple Networks**

The same deployment script works for:

- Local Besu
- Development
- Staging
- Production

Only configuration changes.

### Disadvantages

* Initial setup is more complex than Remix.

* Developers must learn Hardhat configuration and scripting.

## Rationale

ChainDegree is intended to demonstrate production-grade engineering practices rather than contract experimentation.

Hardhat enables repeatable deployment, automated testing, source control integration, and future CI/CD support, making it significantly more suitable than Remix.
